Guidance for AI coding agents (Claude Code, Codex, Cursor, etc.) working in this repo.

## Project

Band Rehearsal Helper — a React + TypeScript + Vite static web app for musical bands. No backend: a public Google Sheet is the database, read via the Sheets API (`src/lib/sheets`, `src/lib/google`). See `README.md` for the full feature list and Google Sheet column schema.

## Setup & commands

- Node `^20.x` required (see `engines` in `package.json`).
- `npm install` — install dependencies.
- `npm run dev` — Vite dev server with HMR, bound to `0.0.0.0` (usable from other devices on the LAN).
- `npm run build` — type-checks (`tsc -b`) then bundles with Vite, output to `docs/`.
- `npm run preview` — serve the production build from `docs/` locally.
- `npm run format` / `npm run format:check` — Prettier.
- There is no test suite yet (`npm test` is a placeholder) and no lint script configured.

## Critical: `docs/` is the deployed site, and it's committed

GitHub Pages serves `docs/` directly from this repo — it is **not** generated by CI, it's **committed source**. After any change under `src/` (or anything else that affects the build output):

1. Run `npm run build` to regenerate `docs/`.
2. Stage both the `src/` changes and the regenerated `docs/` folder.
3. Commit together.

If you change `src/` without rebuilding `docs/`, the live site silently keeps serving the old version. Never hand-edit files under `docs/` — they're build output.

## Architecture notes

- `src/lib/sheets` + `src/lib/google` — Google Sheets data fetching and Google Sign-In (Admin Mode: users with sheet edit access get an in-app Add/Edit UI).
- `src/lib/*` (non-sheets) — mostly local-only, per-device state persisted via `localStorage`: favorites, pins, groups/tags, setlists, line notes, tonality/capo prefs, metronome presets, appearance defaults. None of this is written back to the Google Sheet.
- `src/components/modals/SettingsModal.tsx` — Settings screen, including per-category cache viewers (`CachedSongListModal`) and the destructive "Reset ..." actions for each local cache category.
- `src/hooks/` — one hook per concern (metronome, wake lock, swipe gestures, drag reorder, audio output device, etc.) — check for an existing hook before adding new cross-cutting state logic.
- `src/lib/chords` — chord parsing/transposition engine.
- i18n: `react-i18next`, locale files under `src/locales`, lazy-loaded per language. New user-facing strings must go through `t(...)` with an English source string, not be hardcoded.
- UI primitives (`src/components/ui`) are shadcn/radix-ui based; use the existing `Button` variants (`default`, `outline`, `secondary`, `ghost`, `destructive`, `link`) and sizes rather than ad-hoc styled buttons.

## Conventions

- TypeScript strict — run `npx tsc --noEmit -p .` after non-trivial changes.
- Don't run `npm run build` during regular development — it regenerates the committed `docs/` folder, which just creates diff noise while iterating. Only run it when you actually need to confirm the production build passes (e.g. right before the user commits/pushes, or when debugging a build-only failure), per the `docs/` section above.
- No test suite exists, and none is expected — don't add one or write tests unless the user explicitly asks.
- Prettier formatting is enforced via `lint-staged`/Husky on commit; run `npm run format` if unsure.
- Match existing patterns for new local-cache categories (type in `SongListCategory`, a `reset*` function in `src/lib/*`, wiring in `SettingsModal.tsx`) rather than inventing a new shape.
